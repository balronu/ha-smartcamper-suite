# SmartCamper Suite v0.3.0-beta.1

## Deutsch

### Status

Dies ist die erste öffentliche SmartCamper-Suite-Test-Beta. Sie ist eine
Home-Assistant-Custom-Integration für die kontrollierte parallele Erprobung
von:

- Mobile Fuel Stations
- Camper Route Planner
- Camper Travel Journal

Die Beta basiert auf Merge-Commit
`27bcc53733928310a10391af48cf45be7716714b` und verwendet die getrennte
Domain `smartcamper_suite`.

### Änderungen

- zentrale Fahrzeugverwaltung für die drei Suite-Module;
- gemeinsame Provider-/Credential-Grenzen mit synthetisch getesteten
  Tankerkönig-, Petromap- und Nakordoni-Pfaden;
- zentrale `custom:smartcamper-card` mit Fuel-, Route- und Journal-Ansichten;
- getrennte Suite-SQLite-Dateien einschließlich einer eigenen
  Travel-Journal-Datenbank;
- Journal-Dialoge für Reisen, Aufenthalte, Kosten, Bewertungen,
  Übernachtungen, Unterbrechungen und Zuordnungen;
- automatische, idempotente Lovelace-Ressourcenregistrierung;
- getestetes Setup, Reload, Unload und HA-Koexistenz mit den drei Stable-
  Integrationen;
- HACS-Struktur und versioniertes Frontend-Bundle für die Beta.

### Installation und Sicherheitsgrenzen

In HACS **Pre-Releases aktivieren**, das Repository
`balronu/ha-smartcamper-suite` als Integration hinzufügen und
`v0.3.0-beta.1` auswählen. Danach Home Assistant neu starten und einen
separaten Suite-Config-Entry anlegen. Die drei eigenständigen Stable-
Integrationen bleiben installiert und unverändert.

Für den ersten Lauf nur synthetische oder ausdrücklich freigegebene
Providerdaten verwenden. Die bestehende Journal-Datenbank wird nicht
automatisch migriert und nicht schreibend geöffnet. Der Legacy-Import ist
standardmäßig nicht aktiv und darf zunächst nur als Dry-Run mit einer Kopie
oder Fixture ausgeführt werden.

### Bekannte Einschränkungen

- Nakordoni-Motorhome-Routing ist technisch nur als Beta-/Mock-Grenze
  abgesichert und keine rechtlich validierte Navigation.
- Echte Providerkontingente, Live-Providerverhalten und OAuth-Revoke beim
  jeweiligen Anbieter sind nicht durch einen produktiven API-Aufruf bestätigt.
- Der erste HA-Test ist ein kontrollierter Testlauf, keine Stable-Freigabe.
- Bestehende Dashboards und Automationen werden nicht automatisch migriert.
- Der Grenzwartezeiten-Provider ist nur als Platzhalter enthalten und nicht
  Bestandteil dieser Beta.

## English

### Status

This is the first public SmartCamper Suite test beta. It is a Home Assistant
custom integration for controlled side-by-side testing of Mobile Fuel
Stations, Camper Route Planner, and Camper Travel Journal.

The beta is based on merge commit
`27bcc53733928310a10391af48cf45be7716714b` and uses the separate
`smartcamper_suite` domain.

### Changes

- shared vehicle management for the three Suite modules;
- shared provider and credential boundaries with synthetic Tankerkönig,
  Petromap, and Nakordoni paths;
- one `custom:smartcamper-card` with fuel, route, and journal views;
- separate Suite-owned SQLite storage, including a dedicated journal database;
- journal dialogs for trips, stays, expenses, ratings, overnight records,
  interruptions, and assignments;
- automatic, idempotent Lovelace resource registration;
- tested setup, reload, unload, and HA coexistence with the three Stable
  integrations;
- HACS structure and versioned frontend bundle for this beta.

### Installation and safety boundaries

Enable **pre-releases** in HACS, add `balronu/ha-smartcamper-suite` as an
Integration custom repository, and select `v0.3.0-beta.1`. Restart Home
Assistant and create a separate Suite Config Entry. Keep all three standalone
Stable integrations installed and unchanged.

Use only synthetic or explicitly approved provider data for the first run. The
existing journal database is not migrated automatically and is never opened
for writes by the Suite. Legacy import is disabled by default and must first
be run only as a dry-run against a copy or fixture.

### Known limitations

- Nakordoni motorhome routing is technically covered only as a beta/mock
  boundary and is not legally validated navigation.
- Real provider quotas, live provider behavior, and provider-side OAuth revoke
  have not been validated through a production API call.
- The first HA run is a controlled test, not a Stable release.
- Existing dashboards and automations are not migrated automatically.
- Border-wait forecasting is only a placeholder and is not part of this beta.
