# SmartCamper Suite v0.3.0-beta.5

## Deutsch

Experimentelle UI-Test-Beta auf Main-Commit `3cabcbe249ce7aa55d76ec83e7bd10df92b50ef5`.
Sie ist ausschließlich für einen kontrollierten manuellen HACS-/Frontend-Test
mit Home Assistant 2026.10.1 vorgesehen und keine Stable-Version.

### Änderungen

- Persistente Mehrfahrzeugauswahl über gespeicherte Profile mit freundlichen
  Namen und kompatiblem `vehicle_id`-Fallback.
- Responsiver Lovelace-Editor mit Fahrzeug-Dropdown, modulabhängigen Feldern,
  getrennten Routenkoordinaten und deutscher/englischer Beschriftung.
- Bestätigung vor dem Entfernen eines Fahrzeugs.
- Manuelle Aktualisierung als sicherer Standard für neue Fahrzeuge; bestehende
  gespeicherte Aktualisierungsmodi bleiben erhalten.
- Geheimnisfreie Einzelstatus für Tankerkönig, Petromap und Nakordoni.
- Providerzugänge bleiben global und können von mehreren Fahrzeugen gemeinsam
  verwendet werden; Cache und Inflight-Deduplizierung bleiben aktiv.

### Kontrollierte Testinstallation

1. In HACS das Repository `balronu/ha-smartcamper-suite` als Integration
   hinzufügen beziehungsweise aktualisieren.
2. Vorabversionen aktivieren und `v0.3.0-beta.5` auswählen.
3. Home Assistant neu starten.
4. Unter **Einstellungen → Geräte & Dienste** die Suite öffnen und die
   Integrationsoptionen aufrufen.
5. Wohnmobil mit `device_tracker.wohnmobil_zoe` anlegen und speichern.
6. Opel als zweites Fahrzeug mit einem eigenen synthetischen Tracker anlegen.
7. Provider einzeln aktivieren; keine echten API-Schlüssel eintragen.
8. Module einzeln prüfen und die SmartCamper-Karte im Lovelace-Kartenpicker
   suchen und hinzufügen.
9. Den visuellen Editor bei Desktop- und iPhone-Breite öffnen; Fahrzeug,
   Modulfelder und deutsche/englische Beschriftungen prüfen.
10. Travel Journal, Mobile Fuel Stations und Route Planner getrennt testen.
11. Home Assistant erneut neu starten.
12. Optionen, Fahrzeugprofile, Kartenkonfiguration und Providerstatus erneut
    prüfen. Bei einem Fehler keine weiteren Module konfigurieren, sondern
    Logs, Version, betroffenen Schritt und einen Screenshot sichern.

### Einschränkungen

- Echte Kartenpicker-, HA-Neustart- und HACS-Updateanzeige-Nachweise sind vor
  der Veröffentlichung nicht automatisiert möglich; sie sind Bestandteil
  dieses manuellen Praxistests.
- Keine Live-Providerabfragen, OAuth-Live-Tests oder echten Zugangsdaten in
  dieser Releasevorbereitung.
- Kein Legacy-Import und keine produktive Datenmigration; Legacy bleibt
  ausschließlich Dry-Run-only.
- VM 104 und bestehende Stable-Integrationen dürfen nicht verändert werden.

## English

Experimental UI test pre-release based on Main commit
`3cabcbe249ce7aa55d76ec83e7bd10df92b50ef5`. It is intended only for a
controlled manual HACS/frontend test with Home Assistant 2026.10.1 and is not
a Stable release.

### Changes

- Persistent multi-vehicle selection from saved profiles with friendly names
  and a compatible `vehicle_id` fallback.
- Responsive Lovelace editor with a vehicle dropdown, module-dependent fields,
  separate route coordinates, and German/English labels.
- Confirmation before removing a vehicle.
- Manual refresh as the safe default for new vehicles; stored refresh modes on
  existing installations are preserved.
- Secret-free per-provider status for Tankerkönig, Petromap and Nakordoni.
- Provider access remains global and shareable across vehicles; cache and
  inflight request deduplication remain enabled.

### Controlled test installation

Follow the same twelve-step order above: enable HACS pre-releases, select
`v0.3.0-beta.5`, restart Home Assistant, create two synthetic vehicles with
separate trackers, verify shared provider configuration, find and add the card
from the Lovelace picker, test the visual editor at desktop and iPhone width,
test all three modules, restart again, and verify persistence. Do not enter
real credentials. Stop after the first error and record the exact step, logs,
version, and a screenshot.

### Limitations

- Real card-picker, HA restart, and HACS update-display evidence is intentionally
  deferred to this manual practical test.
- No live provider requests, live OAuth tests, real credentials, legacy import,
  or productive migration are part of this release preparation.
- VM 104 and existing Stable integrations must remain unchanged.
